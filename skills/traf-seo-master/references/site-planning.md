# Plan a new site and monitor a live site

## Before launch

Start with the owner's current brief, existing site code or mockup and available keyword data. Fill six decision fields from evidence. Ask for any material missing input while continuing work that can proceed from the brief.

1. Business, offer and useful result for customers.
2. Market, language, service area and actual customer-facing locations.
3. Products or services, price basis and conditions from the owning source.
4. Two to five real search competitors or first-party SERP observations for the selected queries.
5. CMS, builder or codebase, domain candidates, and the team's publishing path.
6. Available mockups, local HTML, test environment, published routes and account access.

Produce a project brief, keyword-to-page map, information architecture, template requirements and launch checks in the project's existing planning location. Use this order:

| Deliverable | Include |
| --- | --- |
| Project brief | Confirmed facts, unknown inputs, whom a visit should serve, country/language, confirmed domains, publishing authority |
| Keyword map and exclusions | Query, source, date, market, intent, page type, canonical target, evidence of demand, confidence and reasons for rejected queries. Use one primary page per proved intent cluster and resolve overlap against real SERPs. Leave demand `unknown` until account or source evidence exists |
| URL and link plan | Home, category/hub, item/model, local service or point, article, review, comparison, conversion and optional utility pages as applicable. List canonical routes, breadcrumb hierarchy, context links, exclusions, locales and redirects |
| Template specification | Distinct useful content and query promise, first-screen information, metadata examples, accessible controls, real images, schema types and eligible fields based on visible facts |
| Technical and launch plan | Verified builder/CMS capabilities, production HTTPS and chosen host, sitemap/robots/canonical/pagination/hreflang, staging isolation, public readback, analytics consent and key actions, first engine checks and recovery procedure |

A physical branch page needs a real location and useful local detail. For a shop keep price, availability and feed facts aligned. For a catalogue define entity eligibility, facets and sample depth. For reviews and comparison pages prove the actual comparison and distinguish affiliate destination from the evaluated entity. For health, finance and other high-stakes subjects identify the owning qualified reviewer for factual claims. Record builders' editable and hosted limits from actual current settings or official documentation.

With no published URL, work from the owner-supplied HTML, local preview or code and keep actual indexing and traffic for post-launch observation. With a hosted preview, confirm access scope before inspecting it. Before production, check exact route inventory, raw and rendered mobile output, navigation and conversion, private staging controls, consent actions, and applicable content and schema. After approved publishing, read back the production result and retain the launch-date baseline. See [sites and publication](sites-publication.md), [intelligence](intelligence.md) and [localization](localization.md).

## Weekly observation once live

Resolve the intended Search Console property, Yandex Webmaster site, GA4 property/stream and Metrika counter. Prefer a verified authorized read or the owner's raw export. Record market, device, date, timezone, granularity, dimensions and known retention/thresholding/processing gaps. From an empty site preserve the first comparable baseline and revisit once complete intervals exist. A missing account or incomplete window is a named gap.

Compare two complete, comparable seven-day periods in the same source. When demand varies significantly by weekday, compare matching days and keep a longer context for decisions. For search data calculate CTR from clicks divided by impressions, use native aggregate position at the requested grain, and retain hidden/anonymous query caveats. Compare query and landing-page winners and losers, index status by URL/reason, same-profile device/market slices, and release dates. Compare actual organic sessions and intended useful events within their analytics property. Keep visits, search clicks, impressions, index states, AI visibility and paid data distinct. Label aggregate restrictions and sample size. Treat zero-impression CTR and incomplete account exports as unknown. Verify paid tool/account scope and cost before using it.

Each observation retains original export or request, selection, complete windows, sample size, observed delta, plausible explanation, and one next action with a readback date. On request for recurrence use the host's existing scheduler or approved monitoring path with these inputs and ownership. A new site with little data still yields a baseline and concrete URL checks.
